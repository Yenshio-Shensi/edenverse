Publishing Strategy

Google Sites Integration Guide

Three methods for connecting your Edenverse HTML site to your existing Google Sites presence at sites.google.com/view/theedenverse

Strategy Overview

Three approaches. One recommendation.

Option Method Custom Domain Full Design Control Difficulty Cost
A ★ GitHub Pages (standalone) Yes (free subdomain) Full Easy Free
B GitHub Pages + Google Sites link Yes Full Easy Free
C Embed HTML in Google Sites No (Google URL) Limited Medium Free
Option A Recommended

GitHub Pages — Standalone Site

Host the full Edenverse website on GitHub Pages for free. Your site gets a clean URL (yourusername.github.io/edenverse) and you keep complete design control. All 8 pages, the stylesheet, and all character images deploy as-is.

1

Create a GitHub account

Go to github.com and sign up with a free account if you don't already have one. Use a username you're comfortable with — it will appear in your site URL.

2

Create a new repository

Click the + icon → New repository. Name it edenverse (all lowercase). Set it to Public. Do NOT initialize with README. Click Create repository.

3

Upload your Website folder

In the new empty repo, click uploading an existing file. Drag in all 9 files from your Website folder (index.html, all other .html files, styles.css), plus the entire images/ folder. Click Commit changes.

4

Enable GitHub Pages

In your repo, go to Settings → Pages. Under Source, select Deploy from a branch. Choose main branch, folder / (root). Click Save. Wait 2–5 minutes.

5

Your site is live

GitHub Pages will display your URL: https://yourusername.github.io/edenverse. Every page, character image, and link will work immediately. Share this URL from your Google Sites page or Amazon KDP bio.

Advantages
  • Free, permanent hosting
  • Full design — exactly what was built
  • All character images display correctly
  • Fast global CDN delivery
  • Easy to update: just re-upload files
    • Considerations
  • URL includes GitHub username
  • Custom domain requires DNS setup (optional)
  • GitHub account required

    • Optional: Connect a Custom Domain

    If you own a domain (e.g. theedenverse.com), go to Settings → Pages → Custom domain, enter your domain, then add a CNAME record pointing to yourusername.github.io at your domain registrar. GitHub handles the HTTPS certificate automatically.

    Option B

    GitHub Pages + Google Sites Link Strategy

    Keep your existing Google Sites page as the series hub, and use GitHub Pages as the destination for the full-featured HTML site. Link between them strategically.

    1

    Complete Option A first

    Get the GitHub Pages site live at yourusername.github.io/edenverse. This becomes the destination for your full site.

    2

    Update your Google Sites page

    In your Google Sites editor, add a prominent button or banner that links to the GitHub Pages site. Label it "Enter the Full Site" or "Full Series Website". Google Sites handles the outbound link cleanly.

    3

    Cross-link both directions

    On the Edenverse HTML site, the Author page already links to sites.google.com/view/theedenverse/home. This creates a two-way ecosystem — visitors can move between both properties naturally.

    4

    Use Google Sites for blog/news only

    Consider simplifying the Google Sites page to serve as a lightweight announcement board, with the HTML site handling all the deep content (characters, lore, books). Visitors who want more will follow the link. Visitors who just want news stay on Google Sites.

    Option C

    Embed HTML Pages Directly in Google Sites

    Google Sites supports embedding HTML via the Embed block. You can embed individual pages from your GitHub Pages site directly inside Google Sites pages using iframes. This lets you keep one URL while showing the full-featured content.

    1

    Deploy to GitHub Pages first (Option A)

    You need a live URL for each page before you can embed it.

    2

    In Google Sites editor: Insert → Embed

    Click the Insert menu → Embed. Paste the full GitHub Pages URL for the page you want to embed (e.g. https://yourusername.github.io/edenverse/characters.html). Click Insert.

    3

    Resize the embed block to full-width

    Drag the embed block edges to full page width. Set height to at least 900px to avoid scroll clipping. The Edenverse site is responsive and will adapt to the iframe dimensions.

    4

    Create one Google Sites page per section

    Recommended mapping:

    Google Sites "Books" page → embed books.html Google Sites "Characters" page → embed characters.html Google Sites "Lore" page → embed lore.html Google Sites "Contact" page → embed contact.html
    Advantages
  • Single Google Sites URL
  • No separate hosting to manage
  • Familiar Google Sites editor
    • Considerations
  • Double navigation bars visible
  • iframe scrolling can feel clunky
  • Mobile experience is inconsistent
  • Google may limit embed height/width
  • Not recommended for image-heavy pages

    • The Recommendation

    Use Option B — GitHub Pages as the primary full site, Google Sites as the series hub. This gives you the best of both:

    • Your existing Google Sites audience finds the full HTML site through a clear, prominent link.
    • The full site (characters, lore, books, contact) runs at full quality with no iframe degradation.
    • Character images from your Renamed_Assets folder display at full resolution.
    • The Amazon KDP links, contact form, and navigation all function as designed.
    • Both properties link to each other — cross-promoting the same series from two directions.

    Upload Checklist for GitHub Pages

    Everything in your Website\ folder must be uploaded to the repo root:

    ✓ index.html ✓ series.html ✓ characters.html ✓ lore.html ✓ books.html ✓ author.html ✓ blog.html ✓ contact.html ✓ styles.css ✓ images/ ✓ char-eva.jpg ✓ char-ado.png ✓ char-cole.png ✓ char-sullivan.png ✓ char-bors.jpeg ✓ char-gabriel.png ✓ char-eva-ado.png ✓ char-eva-gown.jpg ✓ char-ado-gold.png ✓ char-sullivan-cyber.png ✓ char-bors-military.png

    Important: The images/ folder must be uploaded as a folder, not just its contents. In GitHub's drag-and-drop uploader, drag the entire images folder into the upload area — GitHub will preserve the folder structure automatically.
